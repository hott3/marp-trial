# Slide Creator

Marp形式のスライドを、短く、伝わりやすく、実装可能な形で作るためのスキル。

## 目的

- 1スライド1メッセージを徹底する
- 冗長さを排除し、短い言葉で要点を伝える
- 読みやすさと構造を優先して改善する（既存スライドの保持と競合する場合は、読みやすさと構造を優先する）

## 実行フロー

1. まず入力を把握する

- 対象ファイルを確認し、全体の論旨とページ構成を把握する
- 発表目的・対象読者・発表時間が明示されている場合、この順で優先して反映する：発表目的 > 対象読者 > 発表時間
- 明示がなければ、既存の語調と文脈を維持する

2. スライドごとのメッセージを定義する

- 各スライドの主張を1文で要約する
- 1枚に複数主張がある場合は分割する
- 連続スライドで同じ主張が重複する場合は統合する

3. 文面を簡潔化する

- 冗長な語尾、重複表現、説明過多を削る
- 短文中心に書き換える
- 必要に応じて体言止めを使い、リズムと視認性を上げる

4. スライドパターンを選ぶ

- 主張の性質に合わせて、下記パターンのいずれかを選択する
- レイアウト目的を明確にし、要素を増やしすぎない

5. Marp形式として整える

- 既存frontmatter（theme/paginate/header/footer）を基本維持する
- 全体でデザイン一貫性を保つ
- 必要な場合だけ`style`を最小限追加する

6. 最終チェックを実施する

- 1枚1メッセージ違反がないか
- 箇条書きが長すぎないか
- 比較スライドは比較軸が明示されているか
- 参照や注記は本文と視覚的に区別されているか

## 原則

### 1 Slide = 1 Message

- 1枚に2つ以上の主張がある場合、そのスライドは分割する
- 分割後は、各スライドの見出しと本文が同じ主張を指すようにする

### KISS

- 冗長表現は削除する
- 同じ意味の言い換えが連続する場合は1つに統合する
- 可能な範囲で短く、平易な表現に直す
- 適切な場面で体言止めを使う

### 見出しの扱い

- 「スライドの役割（メタ情報）」をそのまま見出しとして出力してしまうのは避ける
- 「一番伝えたいメッセージ」や「キーワード」そのものを見出しに昇格させてください

### タイポグラフィ

- 聴衆が読む本文は原則18pt以上を前提にする
- 補足情報（注記、出典、脚注）は小さくてよい
- 可読性優先で、1行を長くしすぎない

## スライドパターン

### 引き算のスライド

- 構成要素: メッセージテキスト
- 用途: 強い主張を単体で伝える

### 必要なものだけ足すスライド

- 構成要素: メッセージテキスト + 要素
- テイスト: 図形
- 用途: 最小の視覚要素で理解を補助する

### 参照するスライド

- 構成要素: 図 + 参照先
- 用途: 出典や関連資料を示して信頼性を補強する

### 理解を促すスライド

- 構成要素: 図 + 説明テキスト
- 用途: 概念や関係性の理解を助ける

### 事象に対して理解を促すスライド

- 構成要素: 事象 + 図 + 説明テキスト
- 用途: 具体事例から抽象理解につなげる

### 想像を促すスライド

- 構成要素: 図
- 用途: 余白を使って受け手の解釈を促す

### 比較して伝えるスライド

- 構成要素: 比較された複数情報 + メッセージテキスト
- レイアウト: テーブル、対比構造
- 用途: 差分と選択理由を明確にする

### 納得を促すスライド

- 構成要素: メッセージテキスト
- レイアウト: 箇条書き
- 用途: 根拠を順に示して合意形成する

## 出力ルール

- 既存ファイルを編集する場合は、Marp記法を壊さずに更新する
- 新規作成の場合は、以下の最小テンプレートを起点にする

```markdown
---
marp: true
theme: default
paginate: true
header: "タイトル"
footer: "© YYYY name"
---

# タイトル

メッセージ

---

# 補足タイトル

- 要点1
- 要点2
```

## 作業時の振る舞い

- 不明点が多い場合のみ、先に前提を短く確認する
- 前提が十分な場合は確認待ちせず作成に進む
- 変更は最小差分を基本とし、不要な全面リライトを避ける
- ただし、1枚1メッセージ違反が連続する場合は構成ごと再設計する
